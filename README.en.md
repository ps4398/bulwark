# Bulwark

> [!WARNING]

> AmneziaWG) on servers owned by the user. The developer bears no responsibility for
> any other use of this utility. Before using, ensure that your actions comply with
> the laws of your country.

Infrastructure orchestration utility. Automates deployment, configuration, and monitoring of **VLESS+Reality** (xray-core), **Hysteria2**, and **AmneziaWG** on remote servers via SSH.

🇷🇺 [Русская версия](README.md)

## What it does

- **Protocol deployment** — installs and configures xray-core, Hysteria2, AmneziaWG 2.0 on remote nodes over SSH
- **Bridge-relay routing** — configures xray relay bridges for proxying traffic to exit nodes
- **Telegram bot** — admin panel: node status, traffic, service restart, logs, binary upgrades, speed tests
- **Node wizard** — add and deploy new servers (bridge or exit) through a step-by-step bot dialog
- **Config generation** — Jinja2 templates, automatic secret generation and rotation (UUID, X25519, WireGuard keys)
- **Monitoring & failover** — async ICMP + TCP checks, automatic switchover on node failure


## Architecture

```
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ Bridge 1 │ │ Bridge 2 │ │ Bridge 3 │   Relay nodes
        │ mgmt+bot │ │ single   │ │ single   │   xray relay
        └────┬─────┘ └────┬─────┘ └────┬─────┘
             │             │             │
             └─────────────┼─────────────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │  Exit 1  │ │  Exit 2  │ │  Exit 3  │   Exit nodes
        │          │ │          │ │          │   VLESS + HY2 + AWG
        └──────────┘ └──────────┘ └──────────┘
```

**Bridge modes:**
- **Multi-port** — each exit node gets a dedicated relay port
- **Single-port (443)** — UUID-based routing, all traffic on one port

## Quick Start

**Prerequisites:** Ubuntu 20.04+ / Debian 11+ VPS with root access, Telegram bot token from [@BotFather](https://t.me/BotFather).

```bash
# 1. Download and extract on your VPS
wget -qO- https://github.com/ps4398/bulwark/archive/refs/heads/main.tar.gz | tar xz
cd bulwark-main

# 2. Run interactive setup (configures management bridge)
chmod +x setup.sh
./setup.sh

# 3. Start the bot
systemctl start bulwark-bot

# 4. Open Telegram → send /start to your bot → add exit nodes via wizard
```

## Configuration

| File | Purpose |
|------|---------|
| `.env` | Telegram token, SSH passwords, portal credentials |
| `config/nodes.yaml` | Node inventory (IP, role, region, SSH auth) |
| `config/global.yaml` | Monitoring settings, ports, software versions, AWG params |
| `config/secrets/<node>.yaml` | Auto-generated per-node secrets (UUIDs, keys) |
| `config/templates/*.j2` | Jinja2 templates for protocol configs |

All configs are generated by `setup.sh` on first run. Additional nodes are configured through the Telegram bot wizard.

## CLI Reference

```bash
python cli.py <command>
```

| Command | Description |
|---------|-------------|
| `status [node]` | Status of all nodes or detailed for one |
| `deploy <node> [--protocol xray\|hy2\|awg\|all]` | Deploy protocol stack to a node |
| `redeploy <node> <protocol>` | Redeploy specific protocol config |
| `config sync <node>` | Sync config to node |
| `config show <node> <protocol>` | Show protocol config |
| `monitor` | Run continuous health monitoring |
| `bridge update` | Update bridge routing on all bridges |
| `bridge deploy <node>` | Deploy new bridge node |
| `bridge routes` | Show current bridge routes |
| `node list` | List all nodes |
| `node add` | Interactive node addition |
| `sub show` | Show subscription content |
| `sub generate` | Generate subscription |
| `sub push` | Push subscription to portal |
| `secrets show <node>` | Show node secrets |
| `secrets regenerate <node>` | Regenerate node secrets |
| `awg add-peer <node>` | Add AmneziaWG peer |
| `awg gen-link <node>` | Generate AWG 2.0 link |
| `awg list-peers <node>` | List AWG peers |
| `awg sub add\|list\|show\|revoke` | Manage AWG API subscriptions |
| `management install <node>` | Install Bulwark on remote node |
| `management status <node>` | Check management service status |
| `bot start [--no-monitor]` | Start Telegram bot |

## Telegram Bot (admin panel)

Bot is accessible only to the administrator (ID is set during setup). Management via inline keyboards:

| Category | Capabilities |
|----------|-------------|
| **Monitoring** | Node status (live ICMP+TCP), per-node traffic, uptime stats |
| **Services** | Restart xray / hysteria2 / awg, view logs, journalctl cleanup |
| **Maintenance** | Binary upgrades (GitHub API), speed test, sysinfo, reboot |
| **Infrastructure** | Node addition wizard, enable/disable, failover |
| **Configuration** | Bridge config push, subscription push, portal reload |
| **AmneziaWG** | Peer management, AWG 2.0 link generation |

## Subscription Portal

Optional Flask service. Runs on the management bridge behind a reverse proxy.

**Endpoints** (paths are randomised at setup):
- `GET /<prefix>/<token>` — V2Ray subscription (base64)
- `POST /<prefix>/` — AWG auto-provisioning

```bash
python cli.py management install <bridge_node>
# Listens on 127.0.0.1:8787, proxied via nginx / Cloudflare Tunnel
```
